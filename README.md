# caracal-rag

Caracal RAG - a retrieval-augmented generation toolkit.

## Project structure

```
src/caracal_rag/          package source (src layout)
tests/                    pytest test suite
.github/workflows/ci.yml  CI: lint (ruff) + tests (pytest) on PRs and main
```

## What is caracal-rag?

`caracal-rag` provides a local indexing pipeline that downloads knowledge sources, chunks documents, generates embeddings through a local LiteLLM proxy, and stores vectors in a remote Chroma database. It also exposes an MCP server so an LLM agent can search indexed knowledge.

## Commands

- `python -m caracal_rag check`
- `python -m caracal_rag index`
- `python -m caracal_rag index --source fiteo-api`

## Configuration

Copy `config/sources.example.yaml` into your workspace and configure LiteLLM, Chroma, and source URLs there. Provide secrets via environment variables; do not commit credentials.

## Running the Embedding Pipeline

Embeddings are generated by the indexing pipeline using the configured LiteLLM endpoint. You do not run embeddings separately — they happen automatically when you run `python -m caracal_rag index`.

To run embeddings for a specific source:

```bash
python -m caracal_rag index --source fiteo-api
```

The embedding model and endpoint are configured in `config/sources.example.yaml`:

```yaml
embedding:
  model: text-embedding-3-small
  api_base: http://localhost:4000
```

The `api_base` points to a LiteLLM proxy that exposes an OpenAI-compatible `/v1/embeddings` endpoint. The model name is passed through to LiteLLM, which routes it to the underlying provider.

### Verifying Embedding Configuration

Before running the full index, validate your embedding setup:

```bash
python -m caracal_rag check
```

This validates the configuration and connectivity to LiteLLM and Chroma without modifying the vector database.

## Running the RAG Server (MCP)

The MCP server exposes `search_api(query)` to any MCP-compatible agent. It queries the remote Chroma database and returns the most relevant chunks with source metadata.

### Starting the MCP Server

```bash
python -m caracal_rag mcp
```

The MCP server runs as a persistent process. It reads the same configuration as the indexing pipeline (`config/sources.example.yaml` or environment variables).

### Connecting an MCP-Compatible Agent

The MCP server communicates over stdio using the Model Context Protocol. Any MCP-compatible client can connect by launching the server as a subprocess.

#### OpenCode

Add the caracal-rag MCP server to your OpenCode configuration:

```json
{
  "mcp": {
    "caracal-rag": {
      "command": "python",
      "args": ["-m", "caracal_rag", "mcp"]
    }
  }
}
```

Once configured, OpenCode will discover the `search_api` tool and use it automatically when answering questions about the indexed documentation.

#### OpenClaw

Add the caracal-rag MCP server to your OpenClaw gateway configuration:

```json
{
  "mcpServers": {
    "caracal-rag": {
      "command": "python",
      "args": ["-m", "caracal_rag", "mcp"]
    }
  }
}
```

OpenClaw will register the `search_api` tool and make it available to the agent runtime.

### Manual MCP Test

You can test the MCP server directly using any MCP client. The server exposes a single tool:

```
search_api(query) -> list of relevant chunks with source metadata
```

Example result:

```
Source: fiteo-api
Document: login.md
URL: https://raw.githubusercontent.com/mariuszmarzec/fiteo/master/docs/api/login.md
Content: ...
```

## Full Workflow

1. Configure LiteLLM and Chroma in `config/sources.example.yaml`.
2. Set required environment variables for secrets.
3. Run the indexing pipeline: `python -m caracal_rag index`.
4. Start the MCP server: `python -m caracal_rag mcp`.
5. Connect an MCP-compatible agent (OpenCode or OpenClaw).
6. Ask the agent questions about the indexed documentation.
