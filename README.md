## Overview

Caracal RAG provides a local indexing pipeline that downloads knowledge sources, chunks documents, generates embeddings through a local LiteLLM proxy, and stores vectors in a remote Chroma database. It also exposes an MCP server so an LLM agent can search indexed knowledge.

## Commands

- `python -m caracal_rag check` - Validate configuration and connectivity
- `python -m caracal_rag index` - Run the indexing pipeline
- `python -m caracal_rag index --source fiteo-api` - Index only a specific source
- `python -m caracal_rag mcp` - Start the MCP server

## Configuration

Copy `config/sources.example.yaml` into your workspace and configure LiteLLM, Chroma, and source URLs there. Provide secrets via environment variables; do not commit credentials.

### Source Types

Three source types are supported in the sources list:

#### markdown – index individual markdown files by their raw URLs

Example:
```yaml
- name: fiteo-api
  type: markdown
  urls:
    - https://raw.githubusercontent.com/mariuszmarzec/fiteo/master/docs/api/login.md
    - https://raw.githubusercontent.com/mariuszmarzec/fiteo/master/docs/api/logout.md
    - https://raw.githubusercontent.com/mariuszmarzec/fiteo/master/docs/api/users_get.md
```

#### github_md_doc_dir – recursively fetches all .md files from a GitHub repository directory

This is useful when an entire docs folder should be indexed without listing each file individually.

Example:
```yaml
- name: fiteo-docs
  type: github_md_doc_dir
  repo: mariuszmarzec/fiteo
  path: docs
  branch: master
```

#### local_path – reads markdown files from a local directory

This is useful for including local knowledge bases, project documentation, or example files without needing a GitHub repository.

Example:
```yaml
- name: example_knowledge_funny_jokes
  type: local_path
  path: /path/to/example_knowledge_funny_jokes
```

## Configuration Details

### Embedding Configuration

Embeddings are generated by the indexing pipeline using the configured LiteLLM endpoint. You do not run embeddings separately — they happen automatically when you run `python -m caracal_rag index`.

The embedding model and endpoint are configured in `config/sources.example.yaml`:

```yaml
embedding:
  model: text-embedding-3-small
  api_base: http://localhost:3001/v1/embeddings
```

The `api_base` points to a LiteLLM proxy that exposes an OpenAI-compatible `/v1/embeddings` endpoint. The model name is passed through to LiteLLM, which routes it to the underlying provider.

### Chroma Configuration

```yaml
chroma:
  host: localhost
  port: 3400
  collection: caracal-base
```

## Verification

### Verifying Embedding Configuration

Before running the full index, validate your embedding setup:

```bash
python -m caracal_rag check
```

This validates the configuration and connectivity to LiteLLM and Chroma without modifying the vector database.

## Running the RAG Server (MCP)

The MCP server exposes `search_api(query)` to any MCP-compatible agent. It queries the remote Chroma database and returns the most relevant chunks with source metadata.

### Starting the MCP Server

```bash
python -m caracal_rag mcp
```

The MCP server runs as a persistent process. It reads the same configuration as the indexing pipeline (`config/sources.example.yaml` or environment variables).

### Connecting an MCP-Compatible Agent

The MCP server communicates over stdio using the Model Context Protocol. Any MCP-compatible client can connect by launching the server as a subprocess.

#### OpenCode

Add the caracal-rag MCP server to your OpenCode configuration:

```json
{
  "mcp": {
    "caracal-rag": {
      "command": "python",
      "args": ["-m", "caracal_rag", "mcp"]
    }
  }
}
```

Once configured, OpenCode will discover the `search_api` tool and use it automatically when answering questions about the indexed documentation.

#### OpenClaw

Add the caracal-rag MCP server to your OpenClaw gateway configuration:

```json
{
  "mcpServers": {
    "caracal-rag": {
      "command": "python",
      "args": ["-m", "caracal_rag", "mcp"]
    }
  }
}
```

OpenClaw will register the `search_api` tool and make it available to the agent runtime.

### Manual MCP Test

You can test the MCP server directly using any MCP client. The server exposes a single tool:

`search_api(query) -> list of relevant chunks with source metadata`

Example result:

```
Result 1 (similarity: 0.945):
  Source: fiteo-api
  Document: login.md
  URL: https://raw.githubusercontent.com/mariuszmarzec/fiteo/master/docs/api/login.md
  Type: markdown
  Content:
  ...
```

## Full Workflow

1. Configure LiteLLM and Chroma in `config/sources.example.yaml`
2. Set required environment variables for secrets
3. Run the indexing pipeline: `python -m caracal_rag index`
4. Start the MCP server: `python -m caracal_rag mcp`
5. Connect an MCP-compatible agent (OpenCode or OpenClaw)
6. Ask the agent questions about the indexed documentation

## Environment Variables

### LiteLLM Configuration

Set `EMBEDDING_API_BASE` to override the embedding API base URL:

```bash
export EMBEDDING_API_BASE=http://localhost:3001/v1/embeddings
```

### Chroma Configuration

Set Chroma connection parameters:

```bash
export CHROMA_HOST=localhost
export CHROMA_PORT=3400
export CHROMA_COLLECTION=caracal-base
```

### LiteLLM API Key

Set the LiteLLM API key if required:

```bash
export LITELLM_API_KEY=your-api-key
```

## Adding a New Knowledge Source

To add a new source:

1. Edit `config/sources.example.yaml`
2. Add a new entry under `sources:` following the format above
3. Run the indexing pipeline again: `python -m caracal_rag index`
4. The new source will be indexed and made available to the MCP server

## Updating/Re-indexing Existing Documentation

If documentation has changed:

1. Update the source URLs or configuration
2. Run the indexing pipeline: `python -m caracal_rag index`
3. The pipeline will detect changes and update embeddings
4. The MCP server will reflect the new content on next query

## Scope

### In scope
- Python project setup
- Generic configurable knowledge sources
- Fetching Markdown documentation
- Markdown chunking
- Content hashing/change detection
- LiteLLM-based embeddings
- Remote Chroma storage
- Incremental indexing
- MCP server
- `search_api(query)` MCP tool
- Configuration and environment variables
- Unit tests
- README/documentation
- Example configuration for fiteo

### Out of scope
- Changes to the fiteo backend
- Ktor OpenAPI generation
- Generating openapi.yaml
- Generating docs/api/*.md
- Manually maintaining API documentation
- Creating an OpenClaw/Manul skill
- Implementing business-domain knowledge beyond the configured sources
- Running an LLM agent inside caracal-rag
- Implementing a custom embedding model
- Hosting infrastructure for Chroma unless required for local development/testing
